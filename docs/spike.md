# HyperFrames spike

Date 2026-10-22. HyperFrames 0.8.183, node 26.7, ffmpeg 8.1.2, macOS arm64 (Apple M5 Max).

Decision: **HyperFrames path confirmed.** The spec needs the corrections listed under "Contradicts the spec".

## What was tested

`test/fixtures/spike/` holds a hand-written 1920x1080, 30 fps, 8 s composition (root id `spike`):

| Element | Output time | Source |
|---|---|---|
| clip A `<video>` with `data-media-start="2"` | 0-3 s | src.mp4 2-5 s |
| clip B `<video>` with `data-playback-rate="0.5"` | 3-5 s | src.mp4 0-1 s |
| freeze `<img class="clip">` (source frame 29) | 5-6 s | freeze.png |
| nested composition `compositions/card.html` | 6-8 s | static title |
| `<audio>` | starts 0.5 s, 3 s long | tone.mp3 (440 Hz) |

Clips and still sit in an untimed `<div class="cam" id="cam">`. One paused GSAP timeline registered at `window.__timelines["spike"]` zooms the wrapper 1x to 2x over 0.5-1.5 s, holds, and returns over 2.0-2.5 s. GSAP is `assets/gsap.min.js`, copied from the `gsap@3.15.0` package, so render needs no network. `src.mp4` is `testsrc2` 1280x720 30 fps H.264 yuv420p, untagged for colour, with a visible frame counter. Media is regenerated by `make-assets.sh` and ignored by `test/fixtures/spike/.gitignore`.

Each rendered frame was also compared with source frames N'-1 and N'+1 to catch slips. "Crop" is the top-left 1100x650 region, which excludes the noisy checkerboard of testsrc2.

| 170 | freeze still | 29 | 34.4 / 39.7 | 20.6 / 20.1 | 29 |

Result: frame selection is exact. All nine frames match the expected source frame, with at least 13 dB of margin over either neighbour, and the on-screen counters read 63, 72, 0, 10, 10, 20, 29, 29, 29 as expected. No one-frame slips. `data-media-start` and `data-playback-rate="0.5"` (each source frame shown twice, no interpolation) behave as the spec says.

Absolute PSNR is 34-35 dB full frame and 37-42 dB on the crop, below the 40 dB target. That is resampling and codec loss, not a timing or content error. The reference upscale kernel changes it by under 1 dB (bilinear 34.9, bicubic 34.4), the 1280 to 1920 upscale of a high-entropy noise patch dominates, and the render is CRF 16 H.264. Per the pass rule (exact frame-counter match where codec loss lowers PSNR), this passes. The freeze still matches the last frame of clip B at the identical PSNR (34.42 dB), so the cut from video to still is visually seamless.

## Contradicts the spec

1. **`hyperframes lint` has no `--strict` flag** (`Unknown flag: --strict`). Its options are `--json` and `--verbose`. Use `lint --json` and check `ok` / `errorCount` / `warningCount`; `--strict` (errors) and `--strict-all` (errors and warnings) belong to `render`. Stage 6 and the `hf` script should lint with `--json` and fail on `ok: false` or `warningCount > 0`.
2. **`render --json` prints nothing machine-readable for a single render.** The help says "With --batch, emit exactly one final JSON result document". Without `--batch` the output is the human log plus `@hf-progress {...}` lines. Parse success from exit code, then `ffprobe` the output. The summary (`4.1 MB · 8.0s video · rendered in 6.1s`) is only human text.
3. **`data-no-timeline` goes on the host element in the parent `index.html`**, not only inside the nested file. With it only inside `compositions/card.html` the render waited the full 45 s and warned `sub_timeline_readiness_timeout (still unregistered: card)`. With it on the host the card loads in 0.1 s and the render takes 6 s. Compose must emit `data-no-timeline` on every static card host. Without it a nested composition must register `window.__timelines[<its id>]` itself.
4. **Nested composition shape that works**: host `<div data-composition-id="card" data-composition-src="compositions/card.html" data-start data-duration data-no-timeline>`; the file is a bare `<template id="...">` wrapping `<div data-composition-id="card" data-width data-height>`; the inner composition id equals the host id. Scope CSS under `[data-composition-id="card"]`. Lint was clean.
5. **Doctor `ok` is false on a healthy machine** (optional whisper-cpp, Kokoro, MusicGen checks). Do not gate on it. Check the `Chrome`, `FFmpeg`, `FFprobe` entries in `checks[]` instead.
6. **Untagged sources decode as bt709 in HyperFrames, but ffmpeg PNG extraction assumes bt601.** A freeze still extracted with plain `ffmpeg -vf select=... out.png` came out visibly more saturated than the video (23.9 dB against the video frame vs 34.4 dB after the fix). Extract stills with `-vf "select=eq(n\,N),scale=in_color_matrix=bt709:out_color_matrix=bt709"`, or read the stream's `color_space` from ffprobe and pass that matrix. Tagged recordings (QuickTime, most screen recorders) avoid this, but the freeze step must pass the matrix explicitly anyway.
7. **Timeline registration key** is confirmed as `window.__timelines["<root composition id>"]`, created with `{ paused: true }`. `window.__timelines = window.__timelines || {}` first, as the docs show. The blank template assigns directly.
8. **Browser location**: `~/.cache/hyperframes/chrome/chrome-headless-shell/mac_arm-152.0.7977.30/chrome-headless-shell-mac-arm64/chrome-headless-shell` (Chrome Headless Shell 152, not a full Chrome). Microsoft Edge was not needed.
9. Docs bundled with the package are thin (`node_modules/hyperframes/dist/docs/*.md`); the `hyperframes-core` skill the CLI skill refers to (with `data-automation` volume lanes and `creator-editing-recipes.md`) ships with the plugin, not the npm package, so `data-automation` was not exercised here. The ducking track should confirm the lane syntax from the plugin's skill before relying on it.
10. Render log lines show `drawElement self-verify passed ... psnrDb 73.8` and `captureMode: drawelement`. This is HyperFrames' own capture check, not a source-frame check.

## Not tested

- `data-automation` volume lanes (ducking), `data-volume`, multi-audio mixing.
- Multi-worker rendering (spec says `--workers 1`).
- `--quality draft` and `standard`.
- Transitions across overlapping clips; cross-fades between two videos at once.
- Callout/click overlays inside `.cam` under zoom (plain absolutely positioned children of the wrapper; not rendered here).
- Fonts: the card used the system sans stack; no `@fontsource/inter` loading was tried.
- ElevenLabs timestamps.
